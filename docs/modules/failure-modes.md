# Failure modes and edge cases

Audit of 2026-10-18, started after two avoidable problems were found by accident (apps killed with a Quickshell restart; logout killing the compositor first). Rule for all future work: before calling a component done, ask what happens when it fails, restarts, crashes, runs out of memory, disk or battery, loses the network, or is used at the worst moment (cafe, no charger, unsaved work). Test those paths. Prefer checks that fail closed. Add what can be detected to `bbkos-check`.

Status: **done** = applied and tested; **partly** = applied, part untested; **pending (you)** = needs your sudo or a decision; **open** = known risk, not addressed yet.

## Audit of 2026-10-21 (code, live system, long-run assumptions)

Read: root helpers and installers, the theme/settings engine, the lid/idle/lock scripts, the Quickshell services, the systemd units, GRUB/snapper/pacman scripts, and the live system (`journalctl -p err`, `bbkos-check`, `/sys/power`). All five test suites passed before and after. The code was in better shape than its history suggests; what was found is mostly *assumptions that stop being true over time*.

| Assumption | What breaks when it stops being true | Status |
|---|---|---|
| "A handler named `onOnBatteryChanged` runs" (it targets a property that does not exist; the property is `discharging`) | `ScreenTime`: the "since unplugged" total never reset (live value 18 h against 5 h since boot). `BatteryAlerts`: re-arm on plugging in relied on a percent change | **done**: both now `onDischargingChanged`. Second cause found 2026-10-21: `_wasOnBattery: Power.discharging` was a binding, already flipped when the handler ran, so the first unplug after every shell start was missed (live 21 h against 9 h 51 min since boot; reproduced in a 20-line QML file, 1 reset for 2 unplugs). Now the saved state is compared |
| "A service that exits 0 is fine" | `bbkos-camera watch` ended with 0 when the camera node vanished (driver reload, replug); `Restart=on-failure` then left it stopped for good, and the next call setting was silently not applied | **done**: exits 1; `RestartSec=30` so a missing camera cannot spin every 5 s. Test added |
| "`pacman -Qq` always works" | `bbkos-clean --apply` with an empty installed list would call every AUR folder orphaned and delete them, including the `.git` clones that are the supply-chain review | **done**: refuses on an empty list. Test added |
| "Notification text is small" | A sender could put megabytes in a body; 100 entries are rewritten to disk on every change | **done**: summary and body kept to 2000 characters in history |
| "There is always space to record" | A very_high 60 fps recording writes about 1 GB a minute and fails mid-file on a full disk | **done**: `bbkos-record` refuses under 2 GiB free. Test added |

| An app opens the browser (OAuth from Figma or Spotify) and Hyprland stays on the app's workspace (`misc.focus_on_activate` is `false` by default) | **done for Slack** (owner) and for the terminal hand-off before and after a reload; set to `true` in `hyprland.lua`. A/B with `xdg-open`: off = stayed, on = focus and workspace moved. Figma and Spotify were signed in before the change, so their round trip was not re-observed. **Trade-off:** any app may now take focus, so a background app asking while you type could redirect keystrokes; revert by setting it to `false` |
| AUR leftovers pile up in `~/.cache/yay`, or a careless clean loses the only rollback copy of a vendor-pinned package | **done**: `bbkos-clean` (dry run by default, deletes only untracked files, keeps the newest finished package and every git clone, refuses while yay/makepkg runs, never follows symlinks, leaves non-git folders alone). 6 edge cases tested on a fake cache and applied once on the real one: 211 MB for 4 folders, 91 MB freed, most of it a vendor `.deb` |
| Spotify looks blurry and pixelated | **partly**: it is the only XWayland window (`hyprctl clients`), and XWayland draws at 1x on a 1.5x screen. `spotify-launcher.conf` adds `--enable-features=UseOzonePlatform --ozone-platform=wayland`; a launcher dry run shows the flags, the effect is **not yet confirmed visually** (watch the tray icon, window controls and media keys). Revert: delete the file |
| Volume/brightness OSD and popup shapes looked pixelated; text had coloured fringes | **done**: the software renderer staircased rounded ends, odd logical sizes and 1 px borders landed on half pixels, and Qt Quick used RGB LCD smoothing on the OLED. Fixed with the GPU renderer, even sizes and `Theme.hair`, and `QSG_DISTANCEFIELD_ANTIALIASING=gray`; verified with 8-12x captures of the OSD bar, toggle, slider, Wi-Fi popup and bar. Cost: +54 MB RAM, idle power not measured |
| Default browser for links was Vivaldi | **done**: Zen (`xdg-settings`, `http`/`https`/`html`; `figma://` still opens Figma; `$BROWSER=zen` from the next login). A real link click is untested |
