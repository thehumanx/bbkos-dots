# The bbkOS skill

An agent skill for working on this machine: it carries the rules that were broken before and points an agent to the right doc. Spec `docs/specs/2026-10-20-bbkos-skill-design.md`, plan `docs/plans/2026-10-20-bbkos-skill.md`. For the owner's own use on this machine; it is not meant to work on other hardware.

## Files
- `.claude/skills/bbkos/SKILL.md`: hand-written, at most 200 lines. Seven sections: what bbkOS is, rules, where things live, tools, example requests, where to read, finishing a change. The rules are inline on purpose (a weak model may not follow a link) and each names an exact command or file.
- `.claude/skills/bbkos/modules-index.md`: GENERATED by `scripts/build-skill-index.py` from `docs/modules/*.md` and `docs/decisions/*.md` (title plus first sentence) and from the header comment of every `bbkos-*` command in `dotfiles/bin/.local/bin/` (section `## Commands`). Never edit it by hand. A new command needs a header comment in the form `# bbkos-x: what it does.`, or a usage line followed by a description line, for its entry to be useful.
- `tests/skill/`: `test_index.py` (the generator) and `test_skill.py` (frontmatter, section order, the 200-line cap, every repo path and `bbkos-*` command the skill names exists, the Stow command equals the one in `dotfiles/README.md`, the index is current).

## How agents find it
`.claude/skills/<name>/SKILL.md` inside a project is a project skill path for Claude Code and for opencode (opencode walks up from the working directory to the git root; the folder name must equal `name:`). So a session started in `~/.local/share/bbkos/repo` loads it with no setup. A session started elsewhere (for example in `~`) needs the owner's one-time link, which is NOT created by any script and not part of the Stow packages:

```
mkdir -p ~/.claude/skills ~/.agents/skills
ln -s ~/.local/share/bbkos/repo/.claude/skills/bbkos ~/.claude/skills/bbkos      # Claude Code
ln -s ~/.local/share/bbkos/repo/.claude/skills/bbkos ~/.agents/skills/bbkos      # opencode and other agents that read ~/.agents/skills
rm ~/.claude/skills/bbkos ~/.agents/skills/bbkos               # remove (only the links)
```
Omarchy installs its skill the same way, as links into `~/.agents/skills`, `~/.claude/skills`, `~/.codex/skills` and `~/.pi/agent/skills`. Only the two above are listed here because they are the agents used on this machine; the other agent folders can be added the same way.

## Keeping it current
- After adding or renaming a module doc or decision: `python3 scripts/build-skill-index.py`. The `tests/skill` suite fails until the index matches (`--check` prints a diff).
- To add a rule: one or two lines in the Rules section that name a real command or file, because the tests check those names. Add one whenever a mistake is made twice.
- The generator skips lines starting with `Applied`, `Status`, `Design` or `Task N` when picking a doc's summary, because those lines say nothing about what the doc covers.

## Comparison with Omarchy's skill (2026-10-20)
Omarchy's `default/omarchy-skill/SKILL.md` (392 lines) is for end-user customisation and is self-contained. Adopted from it: a trigger-heavy `description` naming the config paths; "validate Hyprland after every change" (`hyprctl reload` then `hyprctl configerrors`); "do not write version-sensitive syntax from memory"; the read-only installed-copies rule; ask before resets; a list of example requests; a self-documenting command list (generated here instead of by a CLI); links into a second agent folder. Not adopted: unbind-before-rebind (keybindings go through `bbkos-keybinds`) and copying command details into the skill (the docs hold them).
